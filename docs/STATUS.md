## Parser differential (2026-10-28)
Harness: `crates/rn-std/tests/parser_diff.rs` + `tools/parsediff.c` (reference side: links `ref/<ver>/build/liblua.a`,
includes the reference `luac.c` for `PrintFunction`, loads every case with `luaL_loadbufferx` inside one `lua_pcall`,
i.e. exactly luac's C depth, so nesting-limit errors match `luac -p`; validated by the nesting-boundary edge cases).
Per case it compares accept/reject, the full error message (chunk id, line, `near` text), and for accepted chunks the
`lua_dump` bytes (stripped and full) and, for a quarter of the generated cases plus all files/edge cases, the full
`luac -l -l` listing (addresses normalized). Two of our paths are checked: `rn_compiler::load` on a `TestHost` (+ our
listing) and the runtime (`State::load_chunk` on the real heap, `string.dump` of the loaded closure); they must agree too.
- Inputs: all corpus files (vendored test suite, `tests/vm`, `tests/lua`, `bench`; 984), ~13.3k literal/limit edge cases
  (numerals, escapes, long brackets, comments, line-ending variants, all 256 single bytes, precedence, constant folding of
  every binary/unary operator on 22 constants, `<const>` propagation, goto/labels/break, attributes, `global`, named
  varargs, nesting limits at 195..201, locals/upvalues/registers/constants/table-constructor limits, line gaps for
  `abslineinfo`, long names/lines, 21 chunk-name forms for `luaO_chunkid`), every prefix of the 3 KB-or-smaller corpus
  files (510k), and per seed: random truncations, token-level mutations (delete/insert/replace/swap/duplicate/run
  delete/run copy/byte edits) of small and big files, crossovers, a grammar generator (all statements and expressions,
  constant-pool > 255 and register-pressure prefixes, upvalue and `_ENV` contexts, line breaks between tokens), mutated
  grammar output and token soup; binary chunks: reference dumps whole, every prefix of the small ones (216k), random
  truncations and header-byte mutations (load mode "bt").
- Runs: `scripts/parser-diff.sh` (memory cap + timeout). 5.5: ~25.6M cases (seeds 1-10; 2.92M per 2M-generated run);
  5.4: ~24.7M cases. About 13% of the cases are accepted chunks whose dumps/listings were compared (~400 MB of listings and
  dumps per 2M run). Throughput ~85k cases/s on 6 workers (release build).
- Findings: **1 bug** (both versions, shared lexer): a NUL byte in the source is token 0 and `lexerror`'s `if (token)` prints
  no "near" part (`stdin:1: unexpected symbol`); we printed `near '<\0>'`. Fixed in `lexer.rs::lex_error`; regression

Known deviations (5.4):
- (FIXED 2026-10-28, `gc/gen54.rs`) The 5.4 collector control layer is a faithful port of 5.4 `lgc.c`: `incstep` (debt and
  step size in work units, 5.4 traversal costs `1 + alimit + 2*nodes` etc., `GCSWEEPMAX` 100 counted per object, `GCFINMAX`
  10 finalizers per step at cost 50), `setpause` on `GCestimate` (`PAUSEADJ`), `luaE_setdebt` semantics (`restart`, `step`),
  generational `genstep` (minor `youngcollection` + `setminordebt` on total bytes; a stop-the-world `fullgen` when memory grew
  `genmajormul`%; a bad collection sets `lastatomic` and the following steps run `stepgenfull` in incremental mode until a
  collection traverses less than 9/8 of the previous one), `entergen`/`enterinc` (whitening, pause), `luaC_changemode`,
  `luaC_fullgc`; finalizers run where the reference calls them (inside `finishgencycle`, in the `GCScallfin` step, before
  the new debt is set). The object-level machinery (mark/atomic/sweep/ages) stays shared. Remaining source of timing
  differences: object sizes (reference 5.4 `Table` is 56 bytes + 16 per array slot, ours 48 + 9; `collectgarbage("count")`
  values therefore differ, and with them the exact points where steps happen).
- `string.rep('', n)` returns at once (the reference loops `n` times).
- Userdata payloads are 16-byte aligned (5.4 `LUAI_MAXALIGN` is 8; stricter is compatible).
- `table.sort`'s pivot randomization seed comes from `make_seed`, not `clock()+time()` (only reachable for adversarial inputs).
- Extra C symbols stay exported in the 5.4 library (`luaL_alloc`, `luaL_makeseed`, `luaL_openselectedlibs`); 5.4 code never
  references them.
- GC stress 2 in 5.4 generational mode (`RUSTYNAIL_GC_STRESS=2`) does one young collection per safepoint and a major
  (`fullgen`) every 64th step (`STRESS_MAJOR`, `gen54.rs`): objects age to old within a few safepoints and 5.4 majors are
  paced only by memory doubling, so without the periodic major, loops waiting for old garbage (closure.lua's
  `while x[1]`) never ended. Stress 2 is still quadratic for a script that keeps growing one big table (a young
  collection re-traverses every touched old table), unlike the 5.5 engine that switches to an incremental major.
  With stress, gc.lua fails at 205 (stress 2) / 473 (stress 1) in both versions and before this work (its assertions
  assume normal pacing); all other official 5.4 files pass under stress 1/2 in both modes.

Errors/yields travel as `Err(Status)`; `Err(Status::Yield)` must not be treated as an error by `pcall_with`-style code on yieldable paths (it is only returned when `yieldable()`).
3. Light C functions for `rn-capi`: `LUA_VLCF` payloads are `NativeFn` only (`Value::native`). Proposal: capi wraps every C function in a `CClosure` whose upvalue 0 is a light userdata with the C pointer and a trampoline `NativeFn`; `lua_tocfunction`/`lua_pushcfunction` identity then needs a capi-side table. Needs a decision before Phase 5.
4. Reference `lua` runs in generational mode (lua.c), where `__gc` order after one `collectgarbage()` can differ from the incremental order (we reproduce incremental/STW: reverse registration order). e2e scripts avoid depending on it; G3 must revisit.
5. `VarInfoFn`/`OpLoc`: arithmetic/call/concat errors take operands as `Opnd{value, loc}`; the VM should pass `OpLoc::Stack(reg)`, `Upvalue(i)` or `Constant(k)` so A's debug task can name variables (currently messages have no `(local 'x')` suffix, the only known difference in message texts).
6. Hooks: `hook/hook_call/rethook` and `set_hook` exist (event, line only); `lua_Debug`/getinfo plumbing, `luaG_traceexec`, count/line hooks and `HOOKYIELD` are for the debug task.
7. `Proto` is not `PF_FIXED`-aware (binary chunks are always copied); `luaS_new` API string cache not ported (`State::new_str` interns directly); GC params beyond `pause`, incremental and generational modes are unchanged from B2 (barriers are called at every mutation site but are no-ops).
8. Known gap: 5.4-specific variants (`lua_newstate` without seed is the same API; 5.4 GC params, `luaD_pretailcall` is shared, no `PF_VATAB`) are compiled but untested for 5.4; Phase 6b.
