## Deliverables
1. **`vm.rs` — `execute(st, ci)`** for all 85 opcodes of 5.5 including the new `GETVARG` and `ERRNNIL`, `OP_VARARGPREP`, `TBC`, `CLOSE`, `TFORPREP/TFORCALL/TFORLOOP`, `SETLIST` (+`EXTRAARG`), `NEWTABLE` (5.5 vB/vC fields), `CONCAT`, `LEN`, `MMBIN*`, integer/float `FORPREP/FORLOOP` (precomputed iteration count semantics incl. overflow/step-0 errors, float loop), `RETURN/RETURN0/RETURN1`, tail calls, `CLOSURE`, `VARARG`, comparisons with all immediate/constant forms, `EQK/EQI/LTI/...`, `TEST/TESTSET`, `JMP`. Port handler by handler from `lvm.c`; the macro-level semantics (`Protect`, `ProtectNT`, `updatetrap`, `savepc`, `vmfetch`) map to the discipline described below. Lua→Lua calls/returns **reuse the same `execute` invocation** (switch `ci`, as `startfunc`/`ret` do) — no Rust recursion for Lua-to-Lua calls.
2. **`arith.rs` / VM helpers** (`lvm.c`, `lobject.c`): `luaV_finishget/finishset` (the `__index/__newindex` chain loop bounded by `MAXTAGLOOP`=2000 with "'__index' chain too long; possible loop"), `luaV_equalobj`, `luaV_lessthan/lessequal` (int/float/string/`__lt/__le`), `luaV_concat` (in-place multi-operand concat with `__concat`, buffer reuse, "string length overflow"), `luaV_objlen`, arithmetic/bitwise slow paths with metamethod fallbacks and **string→number coercion** (in 5.4+ string arithmetic goes through the string library's metamethods in `lstrlib.c` `stringmetamethods`; the core only handles number/number — check `lvm.c` `luaO_arith`/`luaT_trybinTM` and the string-coercion points `luaV_tonumber_`/`luaV_tointeger` (`cvt2num`) carefully and keep the exact error messages: "attempt to perform arithmetic on a nil value", "number has no integer representation", "attempt to compare two table values", "attempt to compare number with nil", "attempt to concatenate a nil value", etc.).
3. **Performance design (PLAN §5, mandatory):** `vm_unsafe.rs` holds the raw-pointer fast paths. In the loop keep `pc: *const u32`, `base: *mut Value`, `k: *const Value` in locals; reload `base` only after operations that may reallocate the stack (use the debug `stack_gen` assertion to prove no stale use); `trap` flag checked at the reference's points for hooks. Opcode as `#[repr(u8)]` enum → `match` jump table; handlers `#[inline(always)]` when tiny; **all slow paths `#[cold] #[inline(never)]`**; integer/float fast paths inline in arithmetic, comparison and for-loop opcodes; `GETFIELD/SETFIELD/SELF/GETTABUP` use the interned-short-string fast path (`Table::get_short_str`); `GETI/SETI/GETTABLE/SETTABLE` array-part fast path; no allocation and no `Vec` on the call path; `CallInfo` reuse. Release profile as in the workspace `Cargo.toml` (`lto=fat`, `codegen-units=1`).
   **Safepoints:** `check_gc` at the same places as `luaC_condGC`, with `top` raised to `ci.top` first (ARCH contract). Barriers at every store as `lvm.c` does (`luaC_barrier*` — currently no-ops).
4. **Hooks/trap support** (`lua_sethook` semantics: call/return/line/count hooks via `luaG_traceexec`, `luaD_hook`, `CIST_HOOKED`, `allowhook`) — implement the VM side (`trap` field, `traceexec`, `luaD_hookcall`, `rethook`); the `debug.sethook` library comes later.
5. **Error messages with variable info:** if Builder A's `rn_core::debuginfo` (task A4, see `docs/STATUS.md`) has landed, wire it in: `impl ProtoView for Proto`, install the `VarInfoFn`, and replace B3's minimal `chunk_id`/`line_at`/`find_local_name` with it; `luaG_runerror` adds `chunk:line:` position exactly like the reference. If it has not landed yet, leave the hook and note it in the handoff.
6. **Remove `stubvm`**; the facade crate `rustynail` installs the real executor in `new_state`.
7. **Minimal native test library** inside `crates/rustynail/tests/support` (NOT rn-std; Builder A is writing the real library later): `print, type, tostring, tonumber (simple), pairs/next, ipairs, pcall, error, assert, select, setmetatable, getmetatable, rawget, rawset, rawequal, rawlen, unpack-like, collectgarbage("collect"/"count")`, enough to run test programs and compare stdout with the reference.
