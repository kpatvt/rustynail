## Design constraints (from PLAN §4.4–4.6; do not deviate without a STATUS.md question)
- Lua→Lua calls never recurse the Rust stack (B4 implements the loop; B3 provides `CallInfo` management that supports it).
- Stack = one contiguous buffer per thread (`Value`s) with `EXTRA_STACK`, growth via `try_realloc` (ErrMem recoverable), limit `LUAI_MAXSTACK` (find in vendored `llimits.h`/`luaconf.h` for 5.5 — it is not public in 5.5) with the reference's "stack overflow" error. Stack positions held across anything that may reallocate are **offsets** (`StkId` newtype = index), never raw pointers; provide `#[inline]` helpers that return raw pointers only for B4's hot loop, with a debug-only generation counter that asserts no stale pointer use.
- Errors: internal `Result<T, Status>`; the Lua error value lives in the State (`State::error_value`/`set_error`). `pcall`-style protection = Rust `Result` handling in `State::pcall_*` (no unwinding). Memory errors preallocate the "not enough memory" string (as `luaD_seterrorobj` / `memerrmsg`). Error-handler (`xpcall` message handler) support per `luaD_throw`/`luaG_errormsg` semantics.
- Continuations: `CallInfo` has `callstatus` flags (`CIST_*` from `lstate.h`), `k`/`ctx`/`old_errfunc` fields; native functions (Rust fns) are `fn(&mut State) -> LuaResult<usize>`-style with an optional continuation form (decide the exact internal signature, document in ARCH.md §Native functions and ask the orchestrator via STATUS.md **before** B4 depends on it if it needs to change the contracts; Builder A will write `rn-std` against it, so keep it small and stable: args are the stack slice `[func+1, top)`, return the number of results left on top).
- Coroutines are separate `Thread` objects with their own stack/CallInfo list; resume/yield mechanics come in the task after B4, but `Thread` creation, `lua_State`-equivalent layout (**`LUA_EXTRASPACE` bytes before the thread header**, copied from the main thread on `newthread`) and the GC traversal of threads (`traversethread`, stack clearing, open upvalues, `twups` list) are in scope now.

## Deliverables
1. **`state.rs`**: `GlobalState` (Heap, registry table with `LUA_RIDX_GLOBALS`/`LUA_RIDX_MAINTHREAD` per version, per-type metatables, `tmname[]` pre-interned metamethod names, memory-error string, panic hook slot, warn function slot, GC params/state, seed, `l_G` access), `Thread` (the `lua_State`), `State::new(allocator, seed)`, `close_state` (calls `__gc` finalizers and closes pending tbc variables, frees everything), `new_thread`, `free_thread`. API for the safe layers: `push`, `pop`, `top`, `set_top`, `index2value` equivalents are NOT needed (that is rn-capi/auxlib); keep the internal API stack-slot based.
2. **`func.rs`**: `Proto` GC object built from `ProtoData<StrRef>` (`Proto::from_data(&mut Heap, ProtoData) -> LuaResult<Gc<Proto>>`, string constants referenced not copied), `LClosure`/`NativeClosure` (Rust fn pointer + upvalue array; `rn-capi` will later wrap C functions), `UpVal` with open/closed states, `find_upval`, `close_upvals`, `new_tbcupval`, `close` (tbc handling with `__close`, error propagation rules from `luaF_close`/`prepcallclosemth`), `lua_closeslot` semantics.
3. **`meta.rs`** (ltm.c): `fast_tm(&Table, TM)` using the flags byte, `get_tm`, `get_tm_by_obj`, `obj_typename` (honours `__name`), `try_bin_tm`/`try_concat_tm`/`try_bin_assoc_tm` (error messages "attempt to perform arithmetic on a nil value" etc. need variable info from `ldebug` — define a trait/hook `VarInfo` returning an optional `" (local 'x')"`-style suffix; Builder A implements it in the debug task; until then the hook returns empty), `call_tm`, `call_tm_res`, `call_order_tm`, `call_close_tm`, `adjust_varargs`/`get_varargs` helpers.
4. **`call.rs`** (ldo.c): `pre_call` (Lua function: stack check, `CallInfo` push, nil-fill missing params, vararg adjust per 5.5 incl. the named-vararg table `PF_VATAB`; native function: call it and `post_call`), `post_call` / `move_results` (all `nresults` cases incl. `LUA_MULTRET`, tbc closing), `call` / `call_no_yield` with C-call depth accounting (`LUAI_MAXCCALLS`=200, error text "C stack overflow", and "error in error handling" status), `protected_call` (`pcall` core: restores `CallInfo`, stack, open upvalues, `allowhook`, `nCcalls`, closes tbc, applies message handler), `try_func_tm` (`__call` resolution loop), `Thread::grow_stack/shrink_stack/check_stack`, `luaD_seterrorobj`.
5. **`gc/` integration**: traversal & freeing for threads, closures, protos, upvalues, userdata (with user values and metatable), `__gc` finalizer calling through `call.rs` (`GCTM`, with the `allowhook` & error-warning behaviour), `Heap::check_gc` becomes `State::check_gc` at safepoints, `luaC_fullgc` entry used by `collectgarbage("collect")`. Userdata object (`udata`, `Udata0` variants, `nuvalue`, alignment so the payload pointer is `max_align_t`-aligned).
6. **Loader hook**: `State::load_chunk(reader/bytes, chunk_name, mode) -> LuaResult<()>` that calls a registered `fn` pointer (`Loader`) installed by the facade crate (`rustynail`) so `rn-core` does not depend on `rn-compiler`; on success it creates the `LClosure` with `_ENV` upvalue set to globals (`luaD_protectedparser` / `f_parser` semantics incl. upvalue init per `lua_load`).

## Orchestrator decisions on B2's open questions
- **Q1 (registry/main thread access from the GC):** `GlobalState` **owns the `Heap` by value** (boxed so its address is stable) alongside the registry, main thread, metatables, etc. `State::collect` splits the borrow (`let GlobalState { heap, registry, .. } = g; heap.collect(&mut |m| { m.mark(registry); … })`). Threads hold a raw `*mut GlobalState` (non-moving; set once at creation). No raw `*mut Heap` in `State`.
- **Q2 (compile-time `StrRef` anchoring):** there are **no GC safepoints inside `rn_compiler::load` or `Proto::from_data`** (collection only happens at `check_gc` safepoints, which they never call), so strings are safe until the Proto is reachable. Document this invariant at `State::load_chunk` and add a debug assertion that no collection occurs during load. Do not add a "stop GC" flag.
- Barriers stay no-ops until the incremental-GC task, but every mutation site you write (table set, upvalue set, `setmetatable`, closure creation) must already call `barrier`/`barrier_back` as `lgc.h` prescribes.
- B2's findings are accepted (reference GC runs inside `table.concat`/`gsub` even when stopped; address-ordered pointer keys are not differential-tested).
