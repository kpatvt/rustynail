# String cost study (Opus, read-only, base e981bfbb, 2026-11-04)
[M] measured, [X] scratch experiment, [E] estimate. perf self-cycles by symbol, CPUs 3/5, warm=0 for JIT-on. Caveats: inline string work in interpreter/tier-1/trace code not counted; jit_tr_alloc inlines SUB/CHAR/CONCAT/STREQ helpers; table_hash noisy (7% between identical binaries); layout changes move unrelated programs +-4-7%.

## Where string time goes (mean over 10 string-heavy programs, ours JIT-on): strings = 46% of cycles
pattern 17.4%, intern lookup/insert/resize 9.9%, buffer/concat 3.4%, copy 3.3%, compare 3.2%, number format/parse 3.0%, API 2.4%, create 1.8%, hash 1.4%, GC freeing strings 0.3%. LuaJIT on same programs: strings 38% (intern 13.8, pattern 12.4, alloc 8.3, GC 5.7). Pattern matching is NOT a gap (faster than LJ and PUC on find_pat, markdown, gsub_str). We are 0.5-0.9x PUC cycles on string programs (same algorithms) except fmt_* rows and tostring_flt.
Mechanisms: (1) hashing is serial over every byte: 35-46% on 30-40 byte strings (lower/upper/fmt_s/fmt_q/gsub_str); (2) intern: large key sets ~60% of intern_concat is cache misses walking the chain; `"key"..i` interns the number string then the concat (2 interns, LJ 1); string-table resize oscillation: check_sizes at every generational minor GC shrinks/regrows: resize_strtab 12-21% of tostring_int/fmt_d (PUC same); (3) libc memcmp calls 6-17% on char/sub/fmt_*; (4) number formatting: fmt_g via Rust exact formatting falls to Dragon4 bignum (35% of tostring_flt), %g/%f/%x via glibc snprintf + valid_form, malloc'd Vec per string.format; (5) table.concat grows a fresh Vec by realloc (malloc 35% of tconcat), returns 72-byte NumBuf by value per number; (6) lib/sub: ours ~62 cycles per result vs LJ ~11 (hash 14, chain 21, memcmp call 14, jit_tr_alloc dispatch 13).
What LuaJIT does that is available to us under 5.5/5.4: sparse hash (pairs order is observable; harness depends on PUC order under SEED=0), reused tmpbuf, own number formatter (must be bit-exact with printf), trace-time BUFPUT/SNEW fold. NOT available: interning long strings (5.5 distinct objects, external strings, %p/topointer, O(n) hash on creation); must keep lua_tolstring pointer stability, NUL termination, embedded zeros, __concat, LUAI_NUMFFORMAT (5.5 %.15g with %.17g retry; 5.4 %.14g).

## Experiments (cycles variant/control, off/on)
A shrink strtab only when nuse < size/16 (was /4): tostring_int 0.76/0.69, fmt_d 0.81/0.80, geomean 0.990/0.983. B native number formatting (shortest digits for tostring; native %g %.Nf %x/%X/%d with -/0/width; snprintf fallback): tostring_flt 0.49, fmt_x_pad 0.53, fmt_f 0.59, fmt_g 0.67, string_ops 0.92, json 0.99/0.96; fmt_d/fmt_q +1-6%; geomean 0.933. C reused buffer for format/tconcat: tconcat 0.65, fmt_s/fmt_q 0.70, geomean 0.940. D concat with int operands on the stack (<=4): table_hash 0.66/0.64, concat_op 0.89; str_idx_concat_key 1.05 (specialise 2 operands). E Fx-style hasher for 5.5 constant cache + dump `seen`: load_big 0.914. F inline word compare for <=64 bytes: ~1.0 (noise). G 256 fixed one-byte strings: sub_1char 0.88/0.76, json 0.985, but concat_op 1.19 alone (interplay with A). H word-at-a-time multiply-fold hash: lower/upper 0.57-0.62, sub 0.82/0.73, fmt_s 0.73, gsub_str 0.82; regressions: str_idx_concat_key 1.14/1.23, table_hash +5..34% (loses locality on sequential keys), pairs-order vs refrun issue. I long-string eq with on-demand cached hash: 0.93 off, 1.04 on.
ALL TOGETHER: 41 string rows 0.802/0.802 geomean; full sets: programs 0.964/0.961, awfy 0.996/0.990, apps 0.995/0.999, real 0.971/0.989; table_hash 0.58, string_ops 0.87, json 0.94/0.93, load_big 0.89, awfy json 0.92/0.94. Official 5.5 suite passes JIT off and on with all fixes; 24k-line tostring/format/concat check matches PUC (subnormals take slow path).

## Trace-level string support
Exists: SNEW (number to string), CONCAT of 2-3 strings, SUB/CHAR/STREQ as helpers via jit_tr_alloc, inline BYTE. template_engine enters 0 traces; markdown sides abort Nyi(Concat); json aborts CFunc (find/match/format/gsub); alloc helpers exit the trace when a GC step is due (6-12k exits/row). T1 inline one-byte results (sub_1char ~0.5), T2 CONCAT/BUFPUT with int operands and >3 operands (0.75-0.85 on concat rows, markdown Nyi(Concat) sides), T3 inline long-string EQ pre-checks (str_eq_long 165 -> ~60-80), T4 non-aborting helper calls find-plain/format/rep/table.concat (find_plain 260 -> 120-150), T5 GC step inside alloc helpers (2-5%). On json/markdown/template_engine time is pattern matching, interning, gsub callbacks: T1-T6 give 0-5% there.
