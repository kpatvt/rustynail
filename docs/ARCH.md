keep 5.4 compiling and passing** (Phase 6b done: the 5.4 runtime is `cfg(rustynail_lua54)` arms in the shared modules, the 5.5 code paths unchanged) (`cargo xtask check --lua-version 5.4`). Version-specific code lives in `crates/rn-core/src/ver/`,
`crates/rn-compiler/src/v54|v55/`, and `rn-capi`. Port from the *vendored* source for the matching version: `vendor/lua-5.5/src`, `vendor/lua-5.4/src`.

## Crate graph
```
rn-core (values, strings, tables, GC, State, interpreter) <- rn-compiler (lexer/parser/codegen/dump/undump)
rn-core + rn-compiler <- rn-std <- rustynail (safe embedding API)
rn-core (+ rn-std) <- rn-capi (extern "C-unwind" lua_*/luaL_*; rlib + staticlib)
rn-core + rn-compiler + rn-std + rn-capi <- rnlua (rnlua, rnluac)
```
`rn-compiler` depends on `rn-core` only for the contract types below (`protodata`, `host`, `status`, `ver::opcodes`); it must NOT depend on the heap/State.

## Contracts (changes need orchestrator approval; both builders depend on these)
1. **Opcodes** — `rn_core::ver::active::{OpCode, OpMode, OpProps, OP_PROPS, OP_NAMES, NUM_OPCODES}`; generated by `tools/gen_opcodes.py` from the vendored `lopcodes.c`. Numeric order == reference. 5.4: 83 ops; 5.5: 85 (adds `GetVarg`, `ErrNNil`). `OP_SELF` is `OpCode::SelfOp`.
   Instruction encode/decode helpers (`Instruction(u32)`, get/set A/B/C/k/Bx/sBx/Ax/sJ, vB/vC for 5.5) are task **A1** (`rn-core/src/instruction.rs`), tested against `luac -l` output.
2. **`ProtoData<S>`** (`rn_core::protodata`) — the plain-Rust compiled function: compiler/undump **produce** it, the VM **consumes** it (B converts it into the GC `Proto` object). Mirrors `Proto` in the vendored `lobject.h`.
3. **`CompilerHost`** (`rn_core::host`) — string interning services the front end needs (`intern`, `bytes`). Builder A tests with a `TestHost`; Builder B implements it for the real heap.
4. **`rn_compiler::load(host, chunk, chunk_name, mode) -> Result<ProtoData<H::Str>, CompileError>`** — single entry point for text *and* binary chunks. `CompileError.message` is byte-identical to the reference error message.
5. **`Status` / `LuaResult<T>`** (`rn_core::status`) — 1-byte internal error type. Lua error *values* are stored in the State, never inside `Result`.

## ADRs
- **ADR-1 value layout:** 16-byte tagged `Value`; tag byte uses the reference variant numbering (`LUA_V*` from the vendored `lobject.h`) so type tests are mask/compare. No NaN-boxing (64-bit integers).
- **ADR-2 allocation:** all runtime allocation goes through a fallible `Allocator` abstraction (honors `lua_Alloc`, reports `ErrMem`); no `Vec`/`Box` in Lua-reachable `rn-core` structures. **Deviation:** `rn-compiler` builds `ProtoData` with ordinary `Vec`s (allocation failure aborts instead of "not enough memory") — accepted for v1, revisit with `try_reserve`. Source size/nesting limits as in the reference still apply.
- **ADR-3 errors:** `Result<T, Status>`; C-API boundary converts to Rust panic (`resume_unwind`) per PLAN.md §4.5 and `docs/SPIKE_UNWIND.md`.
- **ADR-4 GC:** non-moving, precise, safepoint-only collection; G1 stop-the-world first, then incremental, then generational (PLAN.md §4.6). The object-level machinery (`gc/mod.rs` marking/atomic/sweep, `gc/generational.rs` ages/young sweeps, `gc/obj.rs`) is shared by both versions; the *control layer* is per version: 5.5 in `mod.rs`/`generational.rs` (incremental major collections, `minormajor`/`majorminor`), 5.4 in `gc/gen54.rs` (`cfg(rustynail_lua54)`: `incstep` in work units, `setpause` on `GCestimate`, `genstep` with `genmajormul`, stop-the-world `fullgen` majors, the bad-collection fallback `stepgenfull`/`lastatomic`). The 5.4 control functions are generic over a `Host54` (the `State` in `collect.rs`, or `HeapHost` for the heap-only API) so finalizers run where the reference calls them.
- **ADR-5 binary chunks** are trusted (no verifier); text-only load mode exists for sandboxes.
- **ADR-6 no unsafe outside the allowlist** (PLAN.md §6). Builder A's crates are `#![forbid(unsafe_code)]`. Builder B's unsafe is confined to the modules named in the task brief, each block with a `// SAFETY:` comment.

## Conventions
- Rust 2021, stable toolchain; `cargo fmt`, `cargo clippy -D warnings` clean; `cargo nextest run`.
- Strings are `&[u8]`/`Vec<u8>` (Lua strings are not UTF-8). Never panic on Lua-controlled input.
- Each builder uses its own `CARGO_TARGET_DIR` (A: `/tmp/rustynail-target-A`, B: `/tmp/rustynail-target-B`) to avoid lock contention. Builders do **not** commit; the orchestrator integrates.
- File ownership is disjoint (see each task brief). Cross-boundary change needed ⇒ write the question in `docs/STATUS.md` under "Questions for orchestrator" and stop on that point.

## Native functions and the State layer (B3)
- **Signature (stable; `rn-std` is written against it):** `pub type NativeFn = fn(&mut State) -> LuaResult<usize>;` (`rn_core::state`). Arguments are the stack slice `[func + 1, top)`: `st.args()`, `st.nargs()`, `st.arg(i)` (0-based, `nil` if absent). Results are **pushed on top** (`st.push(v)`; at least `LUA_MINSTACK` = 20 free slots are guaranteed at entry, use `st.check_stack(n)` for more) and the function returns `Ok(n)` = number of results; the call machinery (`post_call`) moves them. Errors: `Err(status)` where the Lua error object has already been pushed by `st.throw_value(v)` / `st.run_error(msg)` / `st.type_error(..)` (`Err(st.run_error(b"..."))`); `Err(Status::ErrMem)` needs no object. Never use `?` on a `Status` from a different source than these raisers.
- **Continuations:** `pub type KFn = fn(&mut State, Status, isize) -> LuaResult<usize>;` used with `st.call_k(func, nres, ctx, Some(k))` / `st.pcall_k(func, nres, errfunc, ctx, Some(k))` (= `lua_callk`/`lua_pcallk`); a native that yields returns `Err(Status::Yield)` after recording `k`/`ctx` in its frame (coroutine task).
- **Light vs closure natives:** `Value::native(f)` is a light native function (`LUA_VLCF`, payload is exactly a `NativeFn`); `Heap::new_cclosure(f, nupvalues)` makes a native closure with upvalues (`CClosure`). `rn-capi` wraps C functions as native closures whose first upvalue holds the C pointer (`lua_tocfunction` identity is a capi concern).
- **Stack positions are indices** (`StkId`), never pointers; only `State::slot_ptr` hands out raw pointers (interpreter hot loop), valid until anything that can grow the stack; `State::stack_gen()` (debug builds) changes on every reallocation.
- **GC safepoint contract:** `State::check_gc()` (and anything that allocates through `State::new_*`) may collect. Live values must be on the stack **below `top`**, in the registry, or in a metatable slot. Rust locals holding `Value`/`Gc` handles across a safepoint are *not* roots: anchor them with `push`. An interpreter frame must raise `top` to `ci.top` before `check_gc` (the reference's `luaC_condGC(L, (savepc, L->top = c), ..)`).
- **Errors across Rust frames:** `Result<_, Status>` all the way (no unwinding). `State::pcall_with(closure, old_top, errfunc)` / `State::pcall(func, nres, errfunc)` are the protected-call primitives; they restore `ci`, hooks, `nCcalls`, close pending `__close` variables and shrink the stack. The error object ends up at `old_top`.
- **Interpreter plug-in:** `State::set_executor(f)` with `ExecuteFn = fn(&mut State, Ci) -> LuaResult<()>` (see `rn_core::stubvm` for a small reference implementation of the frame protocol: `pre_call` returns the new `Ci` for a Lua callee, the loop switches to it; `post_call` pops it; `CIST_FRESH` marks the frame where `execute` must return).
- **Loader hook:** `State::set_loader(Loader)`; the facade installs `rn_compiler::load` (`rustynail::new_state`). `State::load_chunk(chunk, chunk_name, mode)` = `lua_load` (pushes the closure with `_ENV` upvalue = globals, or the error message).

## Rust embedding API (Phase 8) — `crates/rustynail`

A thin safe wrapper with C API semantics over `rn_core::state::State` (no `unsafe`:
`#![forbid(unsafe_code)]`). Public surface: `Lua` (owner of a `LuaState`; `Deref<Target = dyn Stack>`),
`Builder` (libraries, memory/instruction limits, text-only loader, sandbox preset), the sealed trait
`Stack` used only as `dyn Stack` (all operations are inherent methods of `dyn Stack`), `Error`/`ErrorKind`,
`RegistryKey`, small enums. Design rules:
- **Handles cannot escape.** `dyn Stack` is unsized, so a `&mut dyn Stack` (from `Lua`, or the one a
  callback receives) cannot be moved, swapped (`mem::swap` needs `Sized`) or stored; the private
  `Handle { st: State }` behind it is created per callback invocation by the trampoline.
- **Values stay rooted.** No `Value` is exposed; Rust locals hold values only between two stack
  operations that cannot collect, or while the value sits in a stack slot below `top`.
- **Every raising operation is protected** (`State::pcall_with` around the `rn-core` call, error object
  removed and stashed in a reserved registry slot with a sequence number). Returning such an `Error`
  from a Rust function re-raises the original object; other errors are raised as their message.
- **Rust values owned by Lua** (closures, typed userdata) live in a per-state, thread-local table
  (`shared.rs`, keyed by the `GlobalState` address) as `Rc<dyn Any>` under a never-reused 64-bit id. A
  closure is a `CClosure` with `f = call_rust` and upvalues [id, owner userdata, user upvalues...]; a
  typed userdata is a zero-length userdata whose user value 1 is the id. `__gc` (`drop_object`) removes
  the entry; lookups downcast, so forged ids or finalized objects are API errors.
- **Instruction limit** = count hook raising with `throw_base_level`; trampolines re-raise while it is
  unwinding (`Shared::limit_hit`), so neither Lua `pcall` nor a Rust callback swallowing the error can
  stop it. **Memory limit** = `Mem::set_limit`. **Text-only** = a loader that strips `b` from the mode.
- Yield from Rust: the callback returns the `ErrorKind::Yield` marker; the trampoline calls
  `State::yield_k(n, 0, None)` (no continuation: the resume values become the function's results).

## C API (Phase 5) — implemented

`crates/rn-capi` exports every symbol of `lua.h`, `lauxlib.h` and `lualib.h` (5.5.1; 5.4.9 under
`--cfg rustynail_lua54`, deltas in `docs/VERSION_DIFF.md` "Runtime") as
`extern "C-unwind"`; it is built as `rlib` + `staticlib` (no `cdylib`: rustc's version script would
hide the C shim's variadic symbols; link `librn_capi.a` with `--whole-archive` to make a `.so`).

- **Light C functions** are a new value variant `LUA_VLCFC` (payload: the raw `lua_CFunction`, equal
  pointers are `rawequal`); C closures are `CClosure`s with `f` = the foreign-call trampoline and the
  C pointer in `CClosure.cfn`. `rn-core` only knows a "C trampoline" hook (`call::set_c_trampoline`)
  that `rn-capi` installs (`glue::ensure_init`, called by `lua_newstate`, `lua_pushcclosure` and
  hosts such as `rnlua`). `lua_tocfunction` of a Rust-native function returns NULL.
- **Errors/yields** cross C frames as panics (`glue::throw`/`glue::catch`, see UNSAFE.md C3).
  Continuations: `CallInfo.ck` holds the C `lua_KFunction`, `CallInfo.k` the Rust trampoline.
  Hooks: `Thread.chook` + trampoline; hook errors propagate (`HookFn` returns `LuaResult`).
- **Variadics** (`lua_pushfstring`, `lua_pushvfstring`, `luaL_error`, `lua_gc`): ~100 lines of C
  (`csrc/shim.c`) extracting `va_arg`s; formatting is Rust (`fmt.rs`).
- **Allocator**: `lua_newstate(f, ud, seed)` wraps the C allocator (`AllocCtl`, replaceable with
  `lua_setallocf`); states created from Rust report `luaL_alloc` from `lua_getallocf`.
- **Hosts** (`rnlua`) link `rn-capi`, call `ensure_init()` and `exported_symbols()` (keeps the whole
  API linked) and use `-rdynamic`, so `.so` modules resolve `lua_*` from the executable.
- **Verification** (`crates/rn-capi/tests/capi.rs`, `crates/rn-cli/tests/cmodule.rs`): the vendored
  `lua.c` linked with our library runs the official suite; `tests/c/capi_diff.c` (16 sections) prints
  identical output against the reference `liblua.a` and ours, also under GC stress; ABI layouts equal
  the headers; unprotected-error panic output equals the reference; a prebuilt C module
  (`tests/c/samplemod.c`) is `require`d by `rnlua` with output equal to the reference `lua`.
- **Known deviations**: `lua_tocfunction` on Rust natives; `lua_gethook` does not report hooks set by
  `debug.sethook`; the `osize` argument of the allocator is 0 (not the object type) for new blocks;
  `lua_newstate` requires 16-byte aligned blocks from the user allocator.
