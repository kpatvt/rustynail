# Extras, session-release

## lib/char under PGO (systematic, not layout lottery)
15 serial runs on CPU 4: plain 178 Mcyc, PGO 263 Mcyc (1.475x), PGO instructions 0.897x of plain. The same bm3-main build pair gives 178 / 263 as well (plain/b3 1.004, PGO/b3g 1.001), so the slowdown reproduces across two source trees and two PGO profiles.
`perf stat` (user): plain 180.8 M cycles, 892.7 M instructions (IPC 4.94), 142.6 k branch misses, 36.3 k L1d load misses; PGO 262.7 M cycles, 800.8 M instructions (IPC 3.05), 140.1 k branch misses, 37.8 k L1d load misses. Branch and cache misses are equal and negligible: the PGO code has a longer dependency chain or a store-forwarding / latency stall at the same instruction mix (script: `string.char(65 + k % 26, 66, 67)` stored into a ring). Not diagnosed further (no profile taken). It is the largest PGO regression of the set by far (next: lib/m_type 1.068, lib/os_clock 1.068, lib/tonumber_int 1.039, knucleotide 1.030) and is also the 6th largest gap to LuaJIT (PGO 2.515).

## 5.4 build: what is not compiled, and what it costs (sources checked in crates/lua-jit/src/tr)
- `rawget` / `rawset` are not recorded as library calls on 5.4 (record.rs: `L::RAWGET if self.cfg.f2raw && !cfg!(rustynail_lua54)`): lib/rawget_set 0.642x PUC 5.4 (0.057x on 5.5, 11.5x relative; p54/i54 0.887: the JIT gains 11% there).
- `next(t, k)` / `pairs` traversal end not modelled on 5.4 (`gfor_inl: !cfg!(rustynail_lua54)`, next disabled, `Rec::tforcall`): lib/it_next 0.676 vs 0.314 on 5.5; it_next_empty 0.615 vs 0.322.
- Inline `#t` (Tlen fast path in traces, asm.rs `!cfg!(rustynail_lua54)`) off on 5.4: lib/len_tbl 0.713 (5.5: 0.389), tinsert_append 0.437 (0.295), tpack 0.450 (0.312). `lib/len_op` and `str_method_len` are fine (strings).
- Integer-key accesses in the hash part (`int_hash_node`, H1 `hashint`) and `__index`/`__newindex` metamethod array accesses with a metatable (`self.cfg.mm && ... !cfg!(rustynail_lua54)`) are off on 5.4 (alimit bookkeeping): sieve 0.574 (0.190), array_rec 0.457 (0.186), int_rec2 0.189 (0.055), tfront_1k 0.145 (0.018), table_array 0.213 (0.100), tmove 0.396 (0.150), tunpack 0.579 (0.256).
- RETF (frame-leaving stitch) is inert on 5.4, and a handful of policies differ without root cause (VA2 notes): class_middleclass 1.041x PUC 5.4 (0.161x on 5.5; p54/i54 0.912) and programs/metamethods 0.950 (0.155) are the worst: the metamethod-heavy paths (__index functions, __lt/__le, handler frames; Bundles B/S/V) seem not to be effective on 5.4. Not diagnosed further here.
- Net, same programs: ALL (223) p54/PUC54 0.268 vs p55/PUC55 0.231 (5.4 is 1.157x worse relative to its reference); lib 1.185, programs 1.229, corpus 1.185, corpus2 dev 1.121, heldout 1.131, awfy 1.081, jit-trace 1.089, apps 1.090, real 1.058, real_dis 1.050. The JIT gain (plain / JIT off, same build): 5.4 0.354, 5.5 0.314 (pass A) geomean over all 223.
- Outputs: every 5.4 column (plain, PGO, JIT-off, nojit build) equals PUC 5.4's output on all 223 programs, and equals the `.expected` files, no mismatches; all 223 programs run on PUC 5.4 and on our 5.4 builds.
